**Where it comes from:** host-side, not repo-side. It is part of the
built-in bash tool's description text, generated by the fork:
`packages/opencode/src/tool/shell/prompt.ts` L100-106 in the
`C:/Users/Wasiejen/Repos/opencode` fork repo. The host injects that
description into the bash tool schema for every session (planner, worker,
explorer alike). Verified: no match in AGENTS.md, role prompts,
agent/readme/*, handover_task.md, or TODO.md (grep over those trees is
clean — only the plugin/intercept logs echo it).

**Why it exists:** it steers file operations to the dedicated tools
(Glob/Grep/Read/Edit/Write) instead of shell one-liners — the dedicated
tools handle quoting/encoding/permissions without shell-join surprises
(especially relevant on this Windows host), and the host already captures
oversized bash output to a file (L98), making head/tail truncation
redundant. Bash stays for process work: git, node, npm, the gate suites.

**The cp nuance:** the avoid-list names exactly the commands that HAVE
dedicated-tool equivalents (find/grep/cat/head/tail/sed/awk/echo). `cp` is
not on the list because a plain file copy has no dedicated-tool
equivalent (block_transfer is block-level, edit/write are content-level) —
so `cp` via bash is the correct channel for copying a whole file, and the
session's interpretation (cp is allowed) was correct.
